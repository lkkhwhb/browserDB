Why BrowserDB?

The browser's native localStorage is a flat key-value string store. BrowserDB transforms it into a structured document database with the developer experience of MongoDB.

⚡

Lightweight & Fast

Ships as a tiny self-contained bundle. Powered by the reliable uuid package for secure identifier generation.

🔒

Type Safe

Written in TypeScript with full generic support. Collections are strongly typed and the compiler catches mistakes at build time.

🧠

Familiar API

If you know MongoDB, you already know BrowserDB. Same mental model: insertOne, find, updateOne, deleteOne.

📦

Tiny Footprint

Under 7 KB gzipped. Loads instantly via CDN script tag or bundled into Vite / React / Next.js projects.

🛡️

Secure IDs

Generates cryptographically secure UUID v4 identifiers using the official uuid library with crypto.randomUUID fallback.

🔧

Zero Configuration

No database setup, no migrations, no server. Instantiate and start inserting documents immediately in any browser.

Performance

BrowserDB is highly optimized for synchronous read and write operations. Because localStorage operations are blocking, performance is critical to prevent UI stutter.

  • Fast Reads: Methods like findOne and find are optimized to iterate efficiently. Once documents are retrieved, filtering logic executes at native JavaScript speeds.
  • Batched Writes: The insertMany method validates and serializes documents simultaneously before writing, minimizing consecutive I/O bottlenecks.
  • Lightweight: Without the overhead of asynchronous events, Promises, or structured cloning found in IndexedDB, small to medium operations execute in less than a millisecond.

Comparison with IndexedDB

BrowserDB is not meant to compete with IndexedDB. Instead, it is designed to make localStorage easier to maintain and query for small apps, drafts, and user settings. While BrowserDB provides an incredibly fast and simple developer experience, it solves a completely different problem than IndexedDB.

FeatureBrowserDB (localStorage)IndexedDB
API StyleSynchronous, Simple, MongoDB-likeAsynchronous, Complex, Event-driven
Storage Limit~5 MB per originVirtually Unlimited (GBs)
PerformanceInstant for small datasets; can block main thread on huge readsNon-blocking; requires callback/Promise overhead
Data TypesJSON stringifiable (loses Dates, Maps, Sets)Structured Clone (preserves Dates, Maps, ArrayBuffers)
Best ForUser settings, drafts, offline caching, small appsLarge files, massive datasets, complex relational queries

Installation

NPM / Bundler

Install via npm for use in Vite, React, Next.js, or any bundler environment:

Terminal
npm install @lkkhwhb/browserdb

Then import in TypeScript or JavaScript:

TypeScript
import { BrowserDB } from "@lkkhwhb/browserdb";

CDN Script Tag

Load the standalone bundle directly in any HTML page. No bundler or build step required. Here is a working prototype:

HTML
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <script src="https://cdn.jsdelivr.net/npm/@lkkhwhb/browserdb@latest/dist/browserdb.global.js"></script>
</head>
<body>
  <h1>BrowserDB Notes</h1>
  <input id="titleInput" type="text" placeholder="Title" />
  <input id="contentInput" type="text" placeholder="Content" />
  <button onclick="addNote()">Insert Note</button>
  <ul id="notesList"></ul>

  <script>
    const db = new window.BrowserDB.BrowserDB();
    const notes = db.collection("notes");

    async function renderNotes() {
      const list = document.getElementById("notesList");
      list.innerHTML = "";
      const allNotes = await notes.find();
      allNotes.forEach(n => {
        const li = document.createElement("li");
        li.textContent = n.title + ": " + n.content;
        list.appendChild(li);
      });
    }

    async function addNote() {
      const title = document.getElementById("titleInput").value.trim();
      const content = document.getElementById("contentInput").value.trim();
      if (!title) return;
      await notes.insertOne({ title, content });
      document.getElementById("titleInput").value = "";
      document.getElementById("contentInput").value = "";
      renderNotes();
    }

    renderNotes();
  </script>
</body>
</html>

The CDN bundle is self-contained (all dependencies including uuid are bundled) and exposes window.BrowserDB globally.

Quick Start

TypeScript
import { BrowserDB } from "@lkkhwhb/browserdb";

type User = {
    name: string;
    age: number;
};

const db = new BrowserDB();
const users = db.collection<User>("users");

// Insert
const doc = users.insertOne({ name: "John", age: 25 });

// Query
const result = users.findOne({ name: "John" });
// → { _id: "a1b2c3d4-...", name: "John", age: 25 }

// Update
users.updateOne({ name: "John" }, { $set: { age: 26 } });

// Delete
users.deleteOne({ name: "John" });

Collections are created automatically on first use. Documents without an _id receive a cryptographically secure UUID v4. Custom IDs are preserved; duplicates throw a DuplicateKeyError.

CRUD Operations

insertOne

collection.insertOne(document: T): WithId<T>
Inserts a single document. Returns the inserted document with its _id.
TypeScript
const doc = users.insertOne({ name: "Alice", age: 20 });
console.log(doc._id); // auto-generated UUID

insertMany

collection.insertMany(documents: T[]): WithId<T>[]
Inserts multiple documents. Validates the entire batch for duplicate IDs before writing.
TypeScript
users.insertMany([
    { name: "Alice", age: 20 },
    { name: "Bob", age: 24 }
]);

find

collection.find(filter?: Filter<T>): WithId<T>[]
Returns all documents matching the filter. Omit to return every document.
TypeScript
const all = users.find();
const adults = users.find({ age: { $gte: 18 } });

findOne

collection.findOne(filter: Filter<T>): WithId<T> | null
Returns the first matching document, or null.
TypeScript
const user = users.findOne({ name: "Alice" });

updateOne

collection.updateOne(filter, update): { matched: boolean; modified: boolean }
Updates the first matched document using $set.
TypeScript
users.updateOne(
    { name: "Alice" },
    { $set: { age: 21 } }
);
Note: The _id field is immutable. Attempts to change it via $set are silently ignored.

deleteOne

collection.deleteOne(filter: Filter<T>): { deletedCount: number }
Deletes the first matching document.
TypeScript
users.deleteOne({ name: "Alice" });

count & clear

TypeScript
const total = users.count();
users.clear();

Query Operators

Use MongoDB-style comparison operators inside filter objects. Operators enforce strict type checking to prevent coercion bugs.

OperatorDescriptionSupported Types
$neNot equalAll primitives
$gtGreater thanNumber, String
$gteGreater than or equalNumber, String
$ltLess thanNumber, String
$lteLess than or equalNumber, String
TypeScript
users.find({
    age: { $gte: 18, $lt: 65 }
});

Database API

db.collection<T>(name: string): Collection<T>
Gets or creates a typed collection. Created on first use.
db.has(name: string): boolean
Checks if a collection exists in localStorage.
db.dropCollection(name: string): void
Permanently removes a collection and all its documents.
db.clear(): void
Removes all BrowserDB collections from localStorage.
db.stats(): Promise<DatabaseStats>
Returns storage usage metrics including bytes, quota, collection count, and document count.

Storage Statistics

TypeScript
const stats = await db.stats();
// {
//   usedBytes: 1024,
//   usedKB: "1.00 KB",
//   usedMB: "0.00 MB",
//   quotaBytes: 5242880,
//   availableBytes: 5241856,
//   percentUsed: "0.02%",
//   collections: 2,
//   documents: 15
// }

BrowserDB calculates exact byte sizes for its own browserdb_-prefixed keys using TextEncoder, and queries navigator.storage.estimate() for origin-wide quota information when available.

Error Handling

Error ClassThrown When
DatabaseErrorNo browser environment or general storage failure
QuotaExceededErrorlocalStorage quota exceeded (~5 MB)
DataCorruptionErrorStored JSON cannot be parsed
DuplicateKeyErrorInserting a document with an existing _id
TypeScript
import { DuplicateKeyError, QuotaExceededError } from "@lkkhwhb/browserdb";

try {
    users.insertOne({ _id: "existing-id", name: "Duplicate" });
} catch (e) {
    if (e instanceof DuplicateKeyError) {
        console.error("Document ID already exists!");
    }
}

React Integration

Vite + React (TypeScript)

TSX
import React, { useState, useEffect } from "react";
import { BrowserDB, WithId } from "@lkkhwhb/browserdb";

interface Task { title: string; completed: boolean; }

const db = new BrowserDB();
const tasks = db.collection<Task>("tasks");

export function TaskApp() {
    const [items, setItems] = useState<WithId<Task>[]>([]);

    useEffect(() => setItems(tasks.find()), []);

    const addTask = (title: string) => {
        tasks.insertOne({ title, completed: false });
        setItems(tasks.find());
    };

    return (
        <ul>
            {items.map(t => <li key={t._id}>{t.title}</li>)}
        </ul>
    );
}

Architecture

BrowserDB is split into focused, single-responsibility modules for easy maintenance:

FileResponsibility
types.tsType definitions — Document, WithId, Filter, Update, QueryOperators, DatabaseStats
errors.tsCustom error classes — DatabaseError, QuotaExceededError, DataCorruptionError, DuplicateKeyError
utils/uuid.tsSecure UUID v4 generator — official uuid package with crypto.randomUUID fallback
query.tsQuery matching engine with comparison operator support and type enforcement
storage.tslocalStorage abstraction with JSON parsing and quota error handling
collection.tsCollection class implementing all CRUD operations
database.tsMain BrowserDB class — collection management and storage statistics
index.tsPublic API barrel file re-exporting all modules

The build system produces three output formats: ESM (dist/index.mjs), CommonJS (dist/index.js), and IIFE (dist/browserdb.global.js) for direct CDN usage.

Browser Compatibility

BrowserDB targets ES2020 and provides graceful fallbacks for modern APIs.

✓ Chrome 80+ ✓ Firefox 75+ ✓ Safari 13.1+ ✓ Edge 80+ ✓ Mobile Chrome ✓ Mobile Safari ✗ Internet Explorer ✗ Node.js (SSR)

Limitations

Storage quota: Browsers enforce a ~5 MB limit per origin for localStorage. Exceeding this throws QuotaExceededError. For larger datasets, consider IndexedDB.
Environment: BrowserDB requires window and localStorage. It will not work in Node.js, Web Workers, or SSR without polyfills.

Non-serializable types that are not preserved across read/write cycles:

TypeBehavior
DateSerialized as ISO 8601 string; not restored as Date object
Map / SetSerialized as empty object {}
BigIntThrows TypeError during serialization
undefinedOmitted from serialized output
FunctionOmitted from serialized output
Class instancesLose prototype chain; become plain objects
